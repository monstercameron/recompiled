# Reverse-engineering, static-lift, and source-reconstruction discovery — 2026-10-15

This lane stages four software-tool projects with source-backed method and status claims. Three focus on general or legacy application binaries; one is a targeted embedded-firmware architecture plugin. `decomp.wtf` is game-oriented, but it is recorded as the developer tool itself, not as a game reconstruction. No SQLite, generated docs, or central addition manifest was edited.

## Staged projects and evidence

- **WinRecomp** (`Zippingrocks/WindowsRecompTool`) is a new PE32/i386 Windows-to-x64 static-recompilation framework. Its README describes a bounded v0.2 profile, translated C++ slices and generated native projects. `docs/status.md` distinguishes synthetic Windows GUI equivalence from the private E3 target: the latter has been generated for x64 but has not been shown to start/render/play on native Windows. The manifest retains the README's 50/100 roadmap points as a planning score, not a percent-complete claim. The original PE32 executable and application data remain user-provided; the repo is MIT-licensed.
- **Fission** (`fission-systems/Fission`) is an active Rust binary-analysis and experimental source-recovery workspace. The maintainer describes Sleigh-to-p-code lifting, custom NIR/HIR, CFG structuring, type recovery, and an execution differential. Its README says the rebuildable-source goal is not yet reached: compiling one 68-function sample as a unit currently reports 20 missing or duplicate declarations. The evaluation guide gives Windows x86-64 PE as the strongest demonstrated analysis path and warns against broad architecture-parity claims. Input binaries are analyst-supplied; repository license is Apache-2.0.
- **C166/ST10 Architecture Plugin for Binary Ninja** (`idaholab/bn-st10-arch`) adds analysis support for the C166/ST10 embedded instruction families, an underrepresented target family. Its README supports full instruction disassembly but reports only partial Binary Ninja LLIL lifting; the row does not imply complete decompilation. Stable release 6.0.10601 includes Windows, Linux, and both macOS architecture binaries. The plugin is MIT-licensed, while Binary Ninja itself is a required external dependency and firmware is supplied by the analyst.
- **decomp.wtf** (`i12bp8/decomp.wtf`) is a local GUI/MCP workflow for matching decompilation across several console binary formats. The maintainer README says it compiles each candidate with the original project compiler and checks bytes at original addresses, then explicitly marks the project discontinued and the repository archived; v0.10.6 is its last installable version. The software requires the user’s own ROM/disc/program file or a supported project checkout and contains no game code. The repository is MIT-licensed. This project is included as a historical research tool, not an active maintenance recommendation.

All four manifests list primary project pages and GitHub language API endpoints. `programming_language` follows the repositories' GitHub language breakdowns checked on 2026-10-15: C++ for WinRecomp and the C166/ST10 plugin, Rust for Fission, and Python for decomp.wtf. Repository activity timestamps were treated only as status evidence and were not used as project start dates.

## Deduplication and exclusions

Before staging, the four canonical GitHub URLs, IDs, and target names were checked against the read-only SQLite project table, `docs/catalog.json`, all JSON research manifests under `data/research/`, and staged/scratch JSON under `work/`. No project ID, canonical repository, or same tool target was present. `decomp.wtf` occurred only in scratch search artifacts under `work/research-latest/`; it was absent from catalog and staged project manifests. The separate `29-reverse-tools` batch already contains Reko, RetDec, angr, ILSpy, JADX, Vineflower, uncompyle6, and many static-recompiler frameworks; none of those projects were repeated here.

- **NeverD** was reviewed but not staged because GitHub reports no recognized license and the repository did not supply a license file during this check.
- **ghidra-decomp** was reviewed but not staged: it is a small bulk-export wrapper around Ghidra, which is already indexed; no release or independent decompilation engine was documented.
- **pire** and **revenant** were reviewed as broad LLM reverse-engineering orchestrators. They mainly compose existing tools and do not yet document a distinct static-lift or reproducible reconstruction method at the same evidence level as the staged entries.
- Parent-provided game leads were checked separately and handed to the game-research lane: `mstan/SuperMetroidRecomp` is already in SQLite; `freeqaz/rb3-xenon` and `gipson-dev/64CBFD` are distinct game decompilation repositories, so they are not included in this software-tools batch.

`metadata-updates.json` is empty because this review verified new repositories and found no existing catalog row with a corrected status claim that needed a patch.
