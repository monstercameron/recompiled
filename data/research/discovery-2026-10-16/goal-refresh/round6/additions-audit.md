`new-projects.json` is the combined importer-shaped addition manifest; `programming-languages.json` contains one matching language-evidence row for every selected project. `primary-source-audit.json`, `license-audit.json`, `github-primary-snapshot.json`, `research-next-manifest-inventory.json`, `exclusions.json`, and `validation.json` preserve the supporting checks and audit trail. The bundle is staged under ignored `work/` files and has not been imported into the live catalog.

The review covered 112 project-row manifests across `work/research-2026-10-16/`, `work/research-oct16/`, and `work/research-next/`: 1,455 appearances and 1,391 distinct IDs. Of those, 903 were already present in SQLite; 64 repeated-ID appearances across research inputs were collapsed. From the 488 absent IDs, 163 Fan Localization rows were excluded as outside this package and two rows were held for the parent’s direct DOA3/NX1 review. Four additional primary-source finds were independently added: DeTAOOT, DHINAMEPTOR, TH04, and TH09. The resulting 327 projects comprise 91 Decompilations, 88 Recompilations, 11 API Translations, 90 Reimplementations, and 47 Emulators; 248 target games and 79 target software.

Dedupe was checked by ID and normalized canonical repository plus target type, game/software name, and platform against both the requested `c9661a0` SQLite snapshot and the shared current checkout (`6ccc33e`). Each database has 2,298 projects; neither comparison found an ID or repository-target collision. Candidate forks were mapped to their upstream repository before comparing, so distinct target platforms remain separate rows only when the target actually differs. The `research-next/` inventory contains 21 manifests, 258 project-row appearances, and 217 unique IDs. Its 38 IDs absent from the catalog are all represented in this final selection and were deduped against the other research lanes.

For each selected record, the audit retains its originating staged manifest and source URLs. The 303 GitHub repository roots were rechecked for repository metadata, README availability/hash, language-byte totals, latest-release endpoint, fork lineage, and GitHub-recognized license; project target, kind, method, and status are grounded in maintainer project sources. Lemon-Project was checked at its canonical Forgejo repository. One GitHub README request returned 404: `dptug/TerrariaXDK`; it remains a cautious source-recovery entry based on the official C# language map, repository tree, and release record, with current build/playability and license left unclear. GitHub returned empty language maps for five projects, whose language is left unknown. Repository-wide GitHub byte leaders are evidence about repository contents, not necessarily the runtime code: for DHINAMEPTOR the map labels a 1,019-byte HSP extension as ActionScript, while the README identifies `start.hsp` and the Git Trees API reports it at 83,807 bytes, so HSP is recorded with that explanation. Nine incoming project rows (seven repositories) initially had a single maintainer-README source; those direct target/method claims were retained and the final manifest adds current repository/language and available release evidence.

GitHub recognized a standard license for 258 project rows. For 68, no standard license was recognized by repository metadata or the license endpoint; this is recorded as unresolved terms, not as proof that no custom license exists. Lemon’s README/license distinguishes GPL-3.0-or-later Lemon/Eden work from inherited GPL-2.0-or-later yuzu code. A repository license does not establish rights to the original game or software. In particular, DeTAOOT says it distributes no executable or game data but notes resources taken from the original executable; reuse rights for those assets are unresolved. DHINAMEPTOR’s CC0 applies to its repository, not the underlying game. TH04/TH09 repository MIT licenses likewise do not cover the original games or assets. User-supplied copyrighted inputs remain the project-level requirements described by their maintainers.

No supported-kind, required-field, URL, or importer-schema holds remain in the selected rows. The project and language manifests were imported into a temporary copy of the current SQLite database using the repository’s actual importer functions. The copy gained 327 projects, 327 language-evidence rows, and 1,893 source rows; SQLite integrity and foreign-key checks passed. The live database hash was unchanged during validation (`9c39382f37d941abeba1cbb8498251c0ae24cd51473190cdc33bddedfaac9a37`). Of 303 GitHub latest-release requests, 154 returned 404; this means no latest-release result was returned and does not establish that a project has never published a release, since prereleases may not be returned by that endpoint.
